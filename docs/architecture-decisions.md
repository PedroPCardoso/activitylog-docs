# Architecture Decisions (D1–D23)

Complete table of architectural decisions, each the result of a design grilling session.

| # | Decision | Rejected alternative | Rationale |
|---|---|---|---|
| D1 | **iff-committed** is the defining invariant: an Activity persists iff the mutation commits, *when the mutation is transactional*. Outside tx → best-effort. | Sync-in-tx as mere "nice-to-have", tolerating orphans. | Reliable audit trail is worth more than throughput. |
| D2 | **ORM-agnostic core + first-class adapters.** Store needs only `(dialect, SqlExecutor)`; `TransactionRef` passed in `persist()` is a SQL executor bound to the ORM's live tx. One `SqlExecutorStore` reuses dialects/`assertSafeIdentifier`. | One native store per ORM, writing via ORM API. | Requirement: work independent of ORM. Adapter-specific is inevitable (only it reaches the tx handle), but core stays clean. |
| D3 | **iff-committed in adapters is only guaranteed by the explicit transactional helper.** Decorator (`@LogsActivity` TypeORM) and `$extends` (Prisma) are **best-effort convenience with documented gaps**; the iff paths are `auditedUpdate` (TypeORM) and `auditedTransaction` (Prisma). A **coverage matrix** declares, per adapter × operation, where iff holds and where it's best-effort. | Pursuing automatic iff in `$extends`/subscriber. | Prisma `$extends` doesn't deliver the tx client for sibling writes; TypeORM subscriber doesn't fire on `.update()`/QB/bulk. Honesty about coverage is a differentiator, not a weakness. |
| D4 | **Subject/Causer identity:** `*_type` = opaque string (default class name, overridable by morph map); `*_id` = `varchar` universal, storing the stringified PK (bigint/uuid/string). Strong typing only in TS (`subjectRef<T>`). Composite PK out of scope for 1.0. | Tying `subject_id` to the real PK type (JOIN/typed index). | Core doesn't know classes or ORMs; JOIN on `subject_id` is rare in an audit trail, so universality > column typing. |
| D5 | **Context via ALS singleton in core.** Single `AsyncLocalStorage` instance exported from `activitylog-core`, carrying causer/batch/withoutLogging. Core is **shared and deduplicated dep** (`external` in tsup, never bundled in leaves). | Reading context directly from nestjs-cls when present. | Duplicated state in memory → causer disappears silently between adapters (two ALS instances). |
| D6 | **ALS opened early (middleware), causer resolved late.** ALS store opened in **middleware** (robust propagation), holding a reference to the request. Causer is resolved **lazily at `.log()`**, when the guard has already run and `request.user` exists. Interceptor is secondary alternative. | Populating causer in interceptor (eager snapshot). | Guard runs after middleware and before interceptor; RxJS `Observable` for ALS is fragile. Lazy resolve kills both problems. |
| D7 | **Queue boundary = explicit contract.** Helpers `serializeContext()` (enqueuer) + `runWithContext(serialized, fn)` (worker) to propagate causer/batch through the job payload. Default when no context is restored: **null causer (system)** — never guess, never leak. iff-committed continues inside the job tx. | Just a doc note about the limitation, no API. | ALS doesn't cross queue boundaries; without API all boilerplate falls on the user and causer disappears silently. |
| D8 | **Old-values without lock by default (Spatie parity), window documented, lock opt-in.** "Old" = row visible in our tx immediately before our UPDATE (see CONTEXT.md › Old). `lockForDiff: true` for exactness under concurrent writers. | `SELECT ... FOR UPDATE` by default. | Spatie reads `original` from memory without locking; default without lock avoids contention/deadlocks and serves 99% of apps. |
| D9 | **Aggregate = 1 Activity** with `subject_id=null`, `subject_type`=model, `properties={aggregate:true, criteria, changes, affected}`, no `old`. Never expand bulk into N rows by default. Query API gains a scope to include/exclude aggregates. | Separate `*Bulk` type; expand per-row when `affected` is small. | Never fake diff per row; row explosion and fake diff destroy trust. |
| D10 | **`bigint` PK default, `uuid`(v7) configurable.** Sync-in-tx on a single SQL store (common case) → DB assigns bigint on INSERT at no cost; Spatie parity. Outbox/distributed → opt-in for uuid v7 generated on client. `batch_uuid` is uuid regardless. | `uuid` v7 as default. | Don't impose uuid index cost on everyone for an advanced case; default serves 99%, config unlocks the rest. |
| D11 | **`properties` = best queryable type per dialect:** `jsonb` (PG), `JSON` (MySQL), `TEXT` (SQLite). Canonical serialization (keys reordered), not literal. | `json` literal on PG. | `properties` is structured diff, not a byte-for-byte document; querying/indexing enables the query API scopes. |
| D12 | **Outbox deferred beyond 1.0; single `ActivityStore` (no writer/reader split); interface frozen with `persist(activities, ctx?: TransactionRef)`.** Outbox is a future implementation of the same interface (persist→outbox, query→final table); `ctx` enables sync-in-tx today and outbox ignores it tomorrow. | Outbox in 1.0; interface already split writer/reader. | 1.0 doesn't carry unvalidated complexity; writer/reader split is speculative abstraction (rule of three). |
| D13 | **Injection choke point (A05):** `tableName` and any customizable column name pass through `assertSafeIdentifier` before SQL; `subject_type`/`causer_type`/`event`/`log_name`/`subject_id`/`properties` are always bind params. Security spec proves malicious `tableName` rejection. **Boundary:** a custom `store` (external `ActivityStore` implementation) is the user's security responsibility. | Interpolating `tableName` without validation; trusting string values are "safe". | OWASP A05: non-parametrizable identifiers are the only vector; a single choke point is auditable. |
| D14 | **Redaction deny-by-default (A09):** built-in sensitive-name list enabled by default (overridable/disableable), match by name, **deep**, case-insensitive; value → `'[REDACTED]'` (key preserved). Redacts in DiffEngine before persist and before any log. Fail secure (masks/discards on error, never persists raw). | Pure opt-in (user forgets a field → leaks). | Audit log of a `User` would capture password hash/PII/token by default; deny-by-default is the org's fail-secure posture and a real differentiator. |
| D15 | **Exactly 3 packages, neutral `activitylog-` base; ORM support INSIDE framework packages — never a package per ORM.** `activitylog-core` (agnostic Nest/Hono/Fastify), `activitylog-nestjs` (Nest integration independent of ORM — module/DI/context/interceptor work with any store; **TypeORM as internal subpath**), `activitylog-nextjs` (**Prisma + Drizzle as internal subpaths**). | One package per ORM (`activitylog-prisma`/`-typeorm`/`-drizzle`) — explicitly rejected. | Consistency with sibling metrics and simplicity > SEO per ORM. |
| D16 | **Write pipeline order: `capture diff → beforePersist(hook) → redaction → persist`.** Redaction is the final guard; whatever the hook adds is also redacted. Hook **cannot** disable redaction; recording a sensitive field intentionally requires an explicit allowlist, never a bypass. `dontSubmitEmptyLogs` evaluated after redaction (skips late). | `beforePersist` running after redaction / being able to disable it. | A hook that enriches `properties` would reintroduce PII/secrets already cleaned; redaction last closes the vector. |
| D17 | **1.0 anchored on TypeORM; Prisma follows in the same major.** TypeORM demonstrates iff-committed impeccably (`event.databaseEntity` + `event.manager`) and validates the whole stack with minimal caveats; Prisma (iff via `auditedTransaction`, `$extends` best-effort) follows to capture the gap before ZenStack. | Prisma-first (market bet of the plan). | The debut must be "audit trail that never orphans", not "with asterisks"; TypeORM has the lowest execution risk for this. |
| D18 | **Query API: strong types for fixed columns; `properties` stays as free path string.** `activityQuery()` types the structural scopes (`inLog`, `causedBy`, `forSubject`, `forEvent`, `forBatch`, `between`) and returns `Activity`/`ActivityPage`. Filters inside JSON use `whereProperty(path, value | filter)` without trying to infer the subject's shape. Canonical pagination is cursor by `{ createdAt, id }`; offset may exist as future convenience, but is not the base contract. Stores that don't support JSON filters must reject explicitly with a capability error, never pretend partial support. | Generic of subject to type `properties`; offset as primary contract; non-SQL stores trying to interpret filters they can't guarantee. | `properties` is dynamic per hook, redaction, and adapter; typing by subject would give false security. Cursor pairs with the stable ordering of D19. |
| D19 | **`created_at` is UTC generated by the application, with stable ordering `created_at + id`.** Core creates a UTC `Date` at the logical Activity moment, before persisting; migrations store in UTC/ISO type per dialect (`timestamptz` on PG, `datetime(3)`/UTC on MySQL, ISO text on SQLite). Semantics are "event moment", not "commit order"; under concurrency, lists use `created_at` and `id` as tiebreak. Minimum contract precision: milliseconds. | `DEFAULT now()` from DB as primary source; promising commit order; ordering only by timestamp. | Single source in core keeps behavior consistent between stores/dialects and enables stable cursor. Commit order is a DB observation, not a portable promise. |
| D20 | **`LogOptions` composes by precedence, but `logOnly` and `logExcept` are mutually exclusive at the same level.** Precedence: call > `@LogsActivity(entity)` > `forFeature` > `forRoot` > defaults, with shallow merge and arrays replacing arrays. `descriptionForEvent` receives `{ event, subject, diff }`; `beforePersist` receives the assembled Activity and context, runs before redaction (D16), and can mutate/replace the Activity, but cannot disable redaction. `redact:false` is only accepted as an explicit option. `lockForDiff`, `tableName` and `store` stay in the same contract to unlock custom adapters and stores. | `logOnly` + `logExcept` composing by subtraction; `descriptionForEvent(event)` without context; hooks after redaction; deep implicit merge of arrays. | Exclusivity avoids ambiguous rules, context improves DX without coupling ORM, and final redaction maintains the security guard. |
| D21 | **The Prisma adapter keeps the single SQL store and requires explicit `dialect` (`sqlite`/`postgres`/`mysql`) when building that store.** A custom `ActivityStore` eliminates the need for dialect, but `auditedTransaction` only accepts it with the explicit `storeTransactionMode: 'uses-context'` assertion. The transactional helper uses a manual proxy of the delegates from `tx` itself — never `$extends` or the root client — and the executor translates reads/writes to that `tx`'s raw parametrized methods. | Writing via `tx.activity.create()` and requiring a Prisma model for the Activity itself; trying to infer provider via internal APIs/DMMF; applying `$extends` to a transaction client. | Prisma's public API doesn't offer portable provider introspection, transaction clients omit `$extends`, and client-level calls captured by an extension could escape the transaction. Explicit dialect and proxy over `tx` preserve D2 and make the iff guarantee executable. |
| D22 | **Bulk/nested Prisma generates exactly one Aggregate activity per top-level operation, with D9 exact envelope: `{aggregate, criteria, changes, affected}`.** `createMany`/`updateMany`/`deleteMany` use normalized data; nested writes in `create`/`update`/`upsert` are not decomposed nor do they also produce an individual Activity. Relations are recognized only through `relationFields` declared by the consumer. The aggregate stores `subject_type=model` and `subject_id=null`. | Expanding N Activities per row; detecting nested by keys like `set` in any object; inspecting DMMF; recording parent individual + aggregate. | `$extends` observes the top-level call and bulk returns a count instead of old/new per row. Explicit public metadata avoids confusing scalar/JSON operations with relations; one aggregate avoids fake diffs, explosion and double counting. |
| D23 | **The Prisma adapter uses minimal public metadata and portable normalization, never internals.** Each model can declare `idField` (default `id`), `relationFields` (default empty) and `auditFields` (globally omitted fields that private reads should re-include). An explicit `select` must include the identity. Before diff/properties, values are copied and normalized recursively: bigint/Decimal→string, Date→ISO, bytes and null sentinels→tagged objects; ambiguous/non-serializable values fail. `lockForDiff:true` is rejected because Prisma doesn't expose a portable lock on that read. | Inferring identity/relations from DMMF; using JSON content as heuristic; delivering bigint/Decimal/bytes directly to JSON serializer; accepting a lock option with no effect. | The extension needs to work without private APIs. The explicit map makes selection, nested detection, omitted fields and subject deterministic; normalization avoids late failures or silent data loss in the Activity JSON, and lock rejection avoids a false guarantee. |
